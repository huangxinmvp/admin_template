## Workarounds And Fixes Applied

### 1. Docker image pull blocker

Current host access to Docker Hub auth endpoints was not reliable enough for a clean first build.

Workaround used:

- switch pilot Dockerfiles to cached `docker.m.daocloud.io/library/...` base images already available to the host

### 2. Backend build path

Containerized Maven packaging was avoided for the pilot backend image.

Fix used:

- package the backend jar on host first
- copy the built jar into the pilot backend image
- automate that package step inside `scripts/pilot_compose.sh` for `build` and `up --build`

### 3. MySQL 8.4 auth-plugin startup issue

The old `--default-authentication-plugin=mysql_native_password` startup arg was incompatible with MySQL 8.4 and caused the MySQL container to fail health checks.

Fix used:

- remove that startup arg from the pilot Compose baseline

### 4. Timezone mismatch causing fresh tokens to fail

Fresh login tokens initially failed on protected endpoints because:

- MySQL was effectively on `+08:00`
- backend JVM started in `UTC`
- `pwd_update_time` comparisons invalidated newly issued tokens

Fix used:

- align pilot service timezone settings
- set backend JVM timezone explicitly through `JAVA_TOOL_OPTIONS`

### 5. Invalid runtime hostname for Java URI parsing

`AICOOS_CONFIG_AGENT_RUNTIME_BASE_URL=http://agent_runtime:8091` failed inside Java because the underscore host was rejected as an unsupported URI.

Fix used:

- add Compose network alias `agent-runtime`
- switch the backend runtime base URL to `http://agent-runtime:8091`

### 6. First-time admin schema/bootstrap gap

The first empty-volume bring-up still needed base admin schema plus admin seed SQL after the containers were up.

Fix used:

- add `bash scripts/pilot_db_bootstrap.sh`
- make the script import `create.sql` only when `sys_user` is missing
- make the script always import the repeatable `seed-saas-admin.sql`

## Remaining Practical Limits

- first-time pilot DB bootstrap still requires an explicit helper step after `compose up`
  - validated helper: `bash scripts/pilot_db_bootstrap.sh`
- screenshot capture on this workstation is still blocked
  - native `screencapture` returned `could not create image from display`
  - browser evidence for these runs is URL/title plus the capture-failed note, not a real PNG
- the validated build path still depends on locally available mirrored base images or equivalent image access
